# Interactive-Stack-Frame
When you click through the simulation, you will observe the fundamental difference between the RSP (Stack Pointer) and the RIP (Instruction Pointer). This difference is why your control flow statements (while, if, else) are never stored on the stack.   Step-by-Step Execution ArchitectureHere is exactly what the code is doing mechanically when you run the fixed HTML file:1. The main() Setup (RSP moves, RIP ticks forward)
When the program begins, the CPU enters main(). The Instruction Pointer (RIP) reads line 17, and the Stack Pointer (RSP) physically moves up to carve out a 36-byte memory block. This chunk of RAM is dedicated to storing your std::string Name (32 bytes) and your int Age (4 bytes). The RIP then ticks down to line 20 to read the nameAge(Name, Age) command.   2. The Function Jump (Pushing the Return Address)
Before the CPU jumps to the nameAge logic, it needs a bookmark to know how to get back. The CPU takes the hidden Return Address (pointing back to line 21 in main()) and pushes it onto the stack. The RSP moves to accommodate this system data.   3. The nameAge Stack Frame (Pass-by-Reference Pointers)
The RIP jumps to line 0 (the start of nameAge). Because your function uses Pass-by-Reference (std::string& name, int& age), the function does not copy the variables. Instead, the RSP moves again to carve out two 8-byte chunks of memory on the stack. These 8-byte chunks hold the physical memory addresses pointing back to where Name and Age live in the main() stack frame.   4. The while (true) Loop (RIP jumps, RSP freezes)
When the RIP reaches line 3 (while(true)), it enters the loop block. At this exact moment, the RSP completely stops moving. The loop does not require any new data storage, so the stack is entirely frozen. The CPU waits at line 5 for input.   The Fail State: If the user types invalid text (like "Eleven"), the hardware failbit trips. The RIP jumps into the if branch (line 6), executes the cin.clear() and cin.ignore() buffer scrubs, and hits the end of the block.   The Rewind: Here is where the loop actually happens. The CPU violently snaps the RIP backward from line 9, pointing it directly back to line 3 to restart the process. The stack data (RSP) was never touched.   5. The Break (RIP escapes)
When the user finally types a valid integer ("11"), the RIP jumps into the else branch (line 10), scrubs the buffer (line 11), and reads the break keyword on line 12. The break instruction physically commands the RIP to jump out of the loop's memory block and continue down the execution thread.   6. The Annihilation (RSP snaps back)
The function finishes on line 15. The CPU reads the saved Return Address, and the RSP snaps violently back down to where it started before the function call. The stack frame holding your reference pointers is instantly destroyed, and the RIP resumes reading at line 21 in main().   This visualization proves why control flow (while, if) costs zero extra RAM. The logic is locked in the read-only .text segment, and the CPU just bounces the RIP pointer around inside it while the Stack Pointer holds the data steady.
